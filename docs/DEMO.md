# Что записать для сдачи

Сценарий для проекта в `D:\Projects\gaming_mps`. Время ниже — рекомендация,
а не требование конкурса. Достаточно 2–3 читаемых роликов общей длиной около
10–15 минут. Повторять одно и то же ради числа файлов не нужно.

## Подготовка

1. Открой VS Code через «Пуск». Выбери «Файл → Открыть папку» и
   `D:\Projects\gaming_mps`. Открой всю папку, а не отдельный файл.
2. Открой «Терминал → Создать терминал». Команды ниже рассчитаны на PowerShell
   и текущую папку проекта. Если путь другой: `cd D:\Projects\gaming_mps`.
3. Разверни окно, увеличь шрифт терминала. Все 100×44 символа игры должны помещаться.
4. Записывай весь экран с микрофоном, чтобы были видны переходы между кодом,
   терминалом и браузером. В OBS: мастер настройки для записи, в «Источниках»
   добавить «Захват экрана», проверить шкалу микрофона, нажать «Начать запись».
   Сначала сделай пробу на 10 секунд. Настройка описана в
   [инструкции OBS](https://obsproject.com/kb/quick-start-guide).
5. Перед записью закрой прежние QEMU клавишей F10. Не запускай два обычных
   запускателя одновременно: они используют один порт 5555.

## Ролик 1 Проект и сборка

### Версия и структура — около минуты

В терминале выполни:

```powershell
git status --short
git log -6 --oneline
git rev-parse HEAD
```

Первый вывод должен быть пустым. Последний — идентификатор сдаваемой версии.
На GitHub открой этот же main и его историю, затем вкладку Actions с успешными
проверками. Покажи оба результата: `core` и `esp32`. Это сборка на отдельном
сервере, в том числе прошивки в контейнере ESP-IDF.

В дереве VS Code покажи:

- `main/main.cpp` — один основной цикл, UART, время и подключение игр;
- `common/game.h` — общий интерфейс Game: start, handle, update, draw, result;
- `common/menu.cpp` и `common/screen.cpp` — меню и цветная ANSI-отрисовка;
- `games/tetris`, `games/minesweeper`, `games/pong` — отдельные игровые модули;
- корневой `CMakeLists.txt` — состав проекта и подключение ESP-IDF;
- `.gitignore` — исключённые сборки, SDK-настройки, временные файлы.

Объяснение: «Игры написаны на C++17 и исполняются в прошивке. Общая оболочка
передаёт ввод и прошедшее время, рисует экран и управляет паузой. Python на ПК
передаёт клавиатуру, мышь и буфер через UART, игровую механику он не считает».
Не нужно пересказывать каждую строку кода.

### Сборка — около минуты без ожидания

Нажми Ctrl+Shift+B. Либо выполни:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1
```

Покажи начало сборки и финальное `Project build complete`, название
`gaming_mps.bin` и отсутствие ошибок. Ожидание активации SDK можно вырезать;
начало и результат должны остаться читаемыми. Если Ninja пишет `no work to do`,
это корректная повторная сборка. Чистую независимую сборку подтверждает Actions.

Для версии компилятора и среды в отдельном PowerShell:

```powershell
powershell -ExecutionPolicy Bypass
. .\tools\enter.ps1
xtensa-esp32-elf-gcc --version
cmake --version
```

### Doxygen — около минуты

В терминале проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\docs.ps1
```

Doxygen здесь работает без подробного вывода. Возврат к приглашению без ошибки
означает успех; сразу `echo $LASTEXITCODE` должен показать 0.
Открой `docs/html/index.html` в браузере, затем список классов и описание
`Game` или `PongModel`. В VS Code покажи `/** @brief ... */` у класса/функции,
`///<` у полей и `#define CHECK` с описанием в `tests/core.cpp`.
В `Doxyfile` покажи `WARN_IF_UNDOCUMENTED`, `EXTRACT_PRIVATE`, `EXTRACT_STATIC`
и `WARN_AS_ERROR = FAIL_ON_WARNINGS`.

## Ролик 2 Игры — около 6–9 минут

Запусти `Run-QEMU.cmd` из папки проекта либо выполни в терминале:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run.ps1 -NoBuild
```

### Меню и общие действия

Покажи три игры, «Краткую сводку», изменение сложности в обе стороны,
запуск и возврат Q. В любой игре покажи P: подожди пару секунд и продолжи —
таймер и состояние не должны перескочить. R начинает те же условия, C копирует
код, «Играть по коду» + ↑/Ctrl+V + два Enter повторяет старт.
Не утверждай, что код сохраняет текущий прогресс: он сохраняет начальные условия.

### Тетрис

1. Покажи автоматическое падение, сдвиг, поворот, остановку у стены и на фигурах.
2. Заполни ряд, чтобы он исчез и вырос заработок. Покажи первую выплату за заказ.
3. Покажи «Линии», «До уровня» и повышение до уровня 2 после 10 линий.
4. Сравни лёгкую и сложную: стартовый шаг падения 1500 и 500 мс;
   на средней 950 мс. На сложной нет предпросмотра следующей фигуры.
5. Заполни верх поля, дождись «Партия окончена», покажи повтор и возврат.

Если трудно быстро набрать 10 линий, не обещай их без подтверждения. Есть
воспроизводимый тест: закрой свой QEMU и в активированной среде ESP-IDF выполни
`python games/tetris/tests/qemu_smoke.py`. Он реально подаёт ввод прошивке,
удаляет 10 линий, проверяет выплаты и измеряет темп. После него выполни
`powershell -ExecutionPolicy Bypass -File tools/render.ps1 -Name tetris-level-2`
и открой `artifacts/screens/tetris-level-2.png`.
В ролике честно назови это кадром автоматической проверки, восстановленным из UART.
Для ручного повтора того же начала есть код `P2-0G00-0000-02RGG`.

### Сапёр

1. Покажи два разных размера поля и выбор сложности: меняется число динамитов.
2. Открой клетку: видны цифры и раскрытие пустой области. Поставь/сними бандану.
3. На открытой цифре с нужным числом соседних бандан повтори открытие:
   раскроются остальные соседи. Это работает и повторным кликом, и Enter.
4. Отдельно покажи поражение, просмотр всего поля и возврат к результату.
5. Отдельно покажи победу, следующий размер и «Начать заново» с новым кодом.

Для повторяемого короткого сценария введи `P2-0M00-0000-20G5Y` — поле 8×8,
средняя сложность, известный первый ход. Считай координаты с 1 от левого
верхнего угла. У клетки (4,3) уже открыта цифра 1. Поставь бандану в (4,2)
и повторно открой (4,3): соседние безопасные клетки раскроются.
После R поставь ошибочную бандану в (5,2), затем открой (4,3): будет поражение.
Это обычная воспроизводимая партия, не подмена результата.

Для победы в этом поле динамиты стоят в (3,1), (4,2), (6,3), (8,3), (8,4),
(7,5), (8,5), (2,6), (3,6), (7,7). Отметь их и открой остальные клетки.
Банданы сами по себе не дают победу: нужны все безопасные клетки.

### Пин-понг

1. Покажи движение ракетки клавишами и мышью, отскоки от стен и ракеток.
2. Доведи дуэль до 5 очков одной стороны: видны счёт, результат и повтор.
3. Выбери другой скоростной уровень: начальная скорость пробки реально меняется.
4. Покажи выбор сложности: он меняет точность противника, а не скорость пробки.
5. Упомяни разгон: после 10 секунд без очка +10%, дальше каждые 5 секунд,
   предел ×2; новое очко сбрасывает разгон.
6. Покажи бонус с двумя ковбоями. Он предлагается после победы на уровне 3
   при любой сложности. Для короткого видео можно сразу войти по коду
   `P2-6SW5-CD0J-0009T`. Скажи, что запускаешь бонус по коду.

Дополнительные заказы, банданы, P2 и бонус — полезные функции. Они не заменяют
демонстрацию базовой механики и настоящего изменения уровней/сложности.

## Ролик 3 Пошаговая отладка — около двух минут

Один лог GDB по критерию П8 недостаточен: запиши окно с исходником, остановку
на строке и выполнение следующих строк. Ниже порядок для нашего QEMU.
Аппаратный JTAG/SWD этим роликом не подтверждается.

1. Закрой обычный QEMU через F10.
2. В первом терминале проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\run.ps1 -NoBuild -Debug
```

Появится ожидание GDB. Не закрывай этот терминал.

3. Во втором терминале:

```powershell
powershell -ExecutionPolicy Bypass
cd D:\Projects\gaming_mps
. .\tools\enter.ps1
xtensa-esp32-elf-gdb --nx .\build\gaming_mps.elf
```

4. В приглашении `(gdb)` вводи по одной команде и показывай результат:

```text
set pagination off
set confirm off
target remote 127.0.0.1:3333
break app_main
continue
list
print/x $pc
next
print/x $pc
next
print/x $pc
```

`continue` доходит до точки останова. `list` показывает исходник вокруг неё.
`next` выполняет следующую строку. Три значения `$pc` должны отличаться.
Для подсветки текущей строки можно нажать Ctrl+X, затем A: это текстовый режим
GDB; если терминал отображает его плохо, достаточно команд `list` и `next`.
Объясни: «Это начало основного цикла программы; отладчик остановил исполнение,
затем я выполняю строки по одной». Не называй QEMU-соединение физическим JTAG.

5. Заверши: `detach`, `quit`. В первом окне F10 закрывает запускатель.

## Что передать вместе с видео

- Ссылку на GitHub с историей и полный хеш финального main.
- Исходники, CMake, sdkconfig.defaults, .gitignore, Doxyfile, README и tools.
  Не копируй в Git свой SDK, build, Python-окружение и временные artifacts.
- `docs/VALIDATION.md` и `docs/evidence`: реальные логи и актуальные кадры.
- Сгенерированный каталог `docs/html` — в архиве материалов, он намеренно
  исключён из Git. Главная страница должна открываться вместе с остальными файлами.
- Самостоятельную сборку и её лог: GitHub Actions уже проверяет сторонний Linux
  в контейнере ESP-IDF. Для дополнительной проверки Паша или Тёма могут собрать
  свежий клон и сохранить вывод. Выдавать это за выполненную ими проверку нельзя.
- Видео положи отдельными файлами или дай доступные жюри ссылки. В README
  нет обещания уже записанного видео: добавляй ссылку после записи.

сборка и открывающаяся документация. Баллы выставляет жюри; наличие этих
