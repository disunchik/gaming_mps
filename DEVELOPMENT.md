# Разработка сборника

Команда «Промпт, паяльник, три ствола». Дмитрий ведёт общую основу и пин-понг,
Паша — тетрис, Тёма — сапёр. Стек: Windows, ESP-IDF v5.5.1, ESP32, C++17, GCC/CMake/Ninja.

## Изменения контракта после «Основы проекта» — читать Паше и Тёме

Экран расширен до **100×44**, игровое поле — до **72×34** для квадратной
доски Сапёра 16×16 с клетками 4×2. Базовый экран 100×40 опубликован коммитом `47913eb`.
Во втором коммите реализованы Понг, P2 и копирование; описание ниже соответствует
новой версии целиком. Перед работой получить свежий main и сверить заголовки.
Все три игры реализованы; у сапёра есть просмотр поля после партии.
Тетрис объединён из PR №1 с сохранением коммитов Паши; общие API не менялись.
Общий smoke проверяет реальную игру, а `tools/test.ps1` дополнительно запускает
`games/tetris/tests/qemu_smoke.py`. Механика Тетриса включена в CTest
целью `tetris_rules`; подробности алгоритмов — в `games/tetris/README.md`.

| --- | --- | --- |

Строки 0,3,40,43 — отступы. Ячейка (99,43) не выводится, чтобы избежать прокрутки.
Публичные константы Screen: `canvasWidth=100`, `canvasHeight=44`, `fieldX=2`,
`fieldY=5`, `panelX=77`, `width=72`, `height=34`, `panelWidth=21`, `panelHeight=34`.
Игра использует локальные `text/number/frame/fill/cell`, а не абсолютный canvas.
`cell` по-прежнему занимает два столбца, x передаётся **в символах**. Панель:
`panelText/panelNumber`, строки 0..33. Добавлен необязательный
`panelTextAt(x,row,text,color)` с локальным x=0..20; старые методы не изменены.
Вывод обрезается по границам панели, включая отрицательный x.

Мышь в Game::handle: x=0..71, y=0..33; экранные (2,5) уже вычтены оболочкой.
Для клавиатуры и ухода указателя x=y=-1. Не вычитать отступ повторно. Внешние
щелчки не приходят; клики внутри общей области, но вне своей доски, фильтрует игра.

**Логические размеры игр не меняются:** тетрис 10×20, сапёр 8/10/12/14/16.
Тетрис использует `Screen::boardX/boardY`. Сапёр рассчитывает собственный
масштаб квадратных клеток с учётом символа терминала 1:2.

| Доска | Левый край | Верхний край | Клетка, столбцы × строки |
| --- | ---: | ---: | ---: |
| Тетрис 10×20 | 26 | 7 | 2×1 |
| Сапёр 8×8 | 4 | 1 | 8×4 |
| Сапёр 10×10 | 6 | 2 | 6×3 |
| Сапёр 12×12 | 12 | 5 | 4×2 |
| Сапёр 14×14 | 8 | 3 | 4×2 |
| Сапёр 16×16 | 4 | 1 | 4×2 |

Координаты локальны для игрового поля. Мышь Сапёра сначала проверяется
на попадание в доску. Затем смещение делится на ширину и высоту клетки.
Область Screen заканчивается на строке 33, а граница логической доски — на size-1.

### Не меняется: подключение и игровые данные

Сигнатуры пяти методов Game, поля/типы Settings и Result, значения GameId и
Difficulty, прежние события Input остаются совместимыми. Паша меняет только
`games/tetris`, Тёма только `games/minesweeper`. Меню, UART, пауза, повтор,
терминальная кодировка, коды и буфер обмена остаются у общей оболочки.
`start` сбрасывает всю партию, `update(ms)` получает время без пауз, `draw/result`
не имеют побочных эффектов. Никаких собственных задержек, циклов UART и часов.

Полный seed uint32_t, включая 0, сохраняется. Формат текста кода не должен
влиять на RNG игры. Сапёр возвращает реальный первый ход в Result.firstX/firstY;
при заданном первом ходе в Settings автоматически воспроизводит его в start.
У тетриса эти координаты -1. Поле Result.level сообщает фактический уровень.

### Уже действует: P2, копирование, общая оболочка

Новый код **P2-XXXX-XXXX-XXXXX**: 13 значащих символов Crockford Base32,
18 символов с префиксом и дефисами. Кодер и декодер поддерживают **только P2**.
P1 больше не принимается по решению владельца; упаковка P2 не менялась.
Регистр и разделители несущественны; O→0, I/L→1. Сохраняются полный seed,
игра, сложность, стартовый level, первый ход сапёра и CRC16. Это стартовые
условия, не сохранение текущего счёта и партии. Ключи самостоятельно не создавать:
достаточно корректного Settings/Result, кодирование делает `common/code.*`.

P2 упаковывается в 8 байтов, биты нумеруются с младшего:

| Байты | Значение |
| --- | --- |
| 0 | gameId: биты 0..1; difficulty: 2..3; level-1: 4..6; бит 7 равен 0 |
| 1..4 | seed uint32_t, младший байт первым |
| 5 | У сапёра firstX в младшей тетраде, firstY в старшей; у остальных 0 |
| 6..7 | CRC-16/CCITT-FALSE байтов 0..5, младший байт первым |

CRC: poly=0x1021, init=0xffff, xorout=0, refin/refout=false. Base32 идёт старшими
битами вперёд; 65-й, завершающий бит равен 0 и проверяется. Восьмибайтовый пакет
даёт 13 символов без `=`. Пример: `P2-4SW5-CD0J-0228E` — Pong, Normal, level=3,
seed=0x12345678. Это независимый контрольный вектор Python struct/binascii.
У тетриса/Понга публичные firstX/firstY остаются -1. У сапёра код доступен только
после реального первого открытия. Диапазоны level: тетрис 1, сапёр 1..5, Понг 1..4.
`encodeCode` выдаёт P2; `decodeCode` принимает только P2 и при ошибке не меняет
выходные настройки. Игра не вызывает Screen::copyText: его использует оболочка
вне draw. Изменения генерации, нарушающие старые старты, согласовывать отдельно.

Кнопка под полем, клавиша C и пункт паузы копируют код через Windows-запускатель.
`Copy=16`, `CopySucceeded=17`, `CopyFailed=18` добавлены в конец InputType;
прежние значения не перенумерованы; события копирования и подтверждения **не передаются Game**.
Паше/Тёме не нужны WinAPI, OSC52 или код буфера обмена. Во время ввода кода C
остаётся текстом; P/R/Q и Escape по-прежнему принадлежат оболочке.

Техническая панель убрана из `common/stub.*`; собственные Stub удаляют
коллеги при реализации. У игроков не должно быть seed, координат, счётчика событий
или текста внутренних проверок. У тетриса полезны очки/линии/уровень/следующая фигура,
у сапёра размер/сложность/мины/флаги/время. Все цвета брать из Theme.

Только Понг получает ускорение по времени розыгрыша и опциональный четвёртый уровень
с двумя ботами. Эти правила **не относятся к тетрису и сапёру**. Их уровни и
сложности сохраняются. Экран после победы и переходы реализует общая оболочка.

### Исправления ввода и фона

Windows-запускатель кодирует латинские команды по Virtual Key: P/Q/R/C,
WASD/F и буквенный ввод P2 работают независимо от RU/EN. Ctrl/Alt сохраняют
штатные управляющие символы. Во время ввода кода C остаётся текстом.
Игры самостоятельно раскладку не разбирают; методы Game и координаты сохранены.
Копирование в Windows повторяет OpenClipboard до 250 мс при занятом буфере и
подтверждает только фактическую запись.

Канвас занимает 100×44 символа. Screen задаёт Theme::background перед очисткой всего
терминального окна и оставляет этот фон между кадрами: свободная ширина справа
не выглядит чёрной полосой. Растягивать игровые доски и менять boardX/boardY не нужно.
Баланс Понга: игрок 54 столбца/с, боты 36 столбцов/с. Windows передаёт удержание
без ожидания системного автоповтора; отпускание останавливает движение. Мышь
по-прежнему задаёт плавную цель. Обычный UART без событий удержания сохраняет
прежний шаг цели 4 столбца.

### Новые события удержания — Паше и Тёме

В конец InputType добавлены `HeldLeft=19`, `HeldRight=20`,
`HorizontalReleased=21`; прежние значения 0..18 сохранены. UART-последовательности:
`ESC[910~`, `ESC[911~`, `ESC[912~`. Координаты этих событий x=y=-1.
Запускатель Windows передаёт состояние A/D и ←/→ **перед** обычным событием
нажатия; обычные Left/Right и автоповтор сохранены для тетриса, сапёра и меню.
Последняя нажатая из удерживаемых клавиш определяет направление, отпускание
возвращает предыдущую; потеря фокуса снимает все удержания.

Понг использует HeldLeft/HeldRight для непрерывного движения, игнорируя
сопутствующий Left/Right, пока направление удерживается. Мышь перехватывает
управление. `start` снимает удержание. Оболочка пропускает новые события
в `Game::handle` также **на паузе**, чтобы отпускание не оставляло ракетку
залипшей; `update` на паузе не вызывается. В меню и вводе кода эти события
поглощаются. **Паша и Тёма могут их игнорировать** (ветка default), сохранив
обычные Left/Right; переход на непрерывное управление не требуется.
Аппаратные кнопки в будущем могут выдавать эти же события через GPIO-адаптер;
его и физический ESP32 в этом изменении не реализовывали и не проверяли.

### Оформление и настройки

Размеры поля/панели, P2 и настройки игр не менялись. В Понге меловое табло и
символ пробки `◉`; геометрия/отражения мяча прежние. Надписи авторов:
«01 / КОВБОЙ ПАША», «02 / КОВБОЙ ТЁМА», «03 / КОВБОЙ ДИМА».
Правила оформлены общей афишей салуна. Текст разработки/диагностики убран
с игровых экранов; сапёр пока остаётся заглушкой, это отражено в документации.
Не возвращать технические статусы в интерфейс игрока.

Во всех настройках `<` уменьшает, `>` увеличивает: локальная строка меню
принимает ЛКМ в абсолютных x=19..52 / 53..80 соответственно. Стрелки нарисованы
в x=42/64. Абсолютные строки настроек: сложность y=16, уровень/размер y=19,
начать y=23, назад y=25. Видимые строки и зоны клика используют одни константы.
Сложность ограничена 0..2; уровень Понга 1..3, размер сапёра 1..5.
Клавиатура и запоминание настроек прежние.

Фон меню: перекати-поле 3×2 символа сдвигается на столбец каждые 160 мс,
полный цикл 16,96 с. Его рисует оболочка до непрозрачного меню, поэтому оно
скрывается за рамкой и остаётся позади кактусов. Фаза обновляется в Menu::update,
а draw остаётся чистым; анимации нет на игровых экранах, паузе и результатах.
Она не использует seed/RNG и не прибавляет игровое время. API игр и размеры
канваса, поля и панели для этого изменения не менялись.
Воспроизводимость предполагает одну версию правил и одинаковый ввод.

### Проверки и синхронизация

Получить свежий main перед работой и сверить эти размеры с `common/screen.h`.
Не переносить обратно старые 80×30/52×20 при слиянии веток. Общие тесты, ANSI-модель,
нативная проверка Windows и рендер снимков используют 100×44. Проверку
Windows-консоли нужно выполнять на Windows. Новые собственные
проверки должны использовать константы и boardX/boardY вместо прежних координат.
Общие тесты больше не требуют счётчиков событий, координат и seed на панели.
При замене последней заглушки нужно адаптировать только ожидания её экрана;
игра не обязана подделывать заглушку ради тестов. Проверять настоящую механику, сборку и QEMU.

## Начало работы

Коллеги клонируют репозиторий **после публикации проверенного коммита «Основа проекта»**.
Паша создаёт ветку `tetris`, Тёма — `minesweeper`, Дмитрий — `pong`.
Работа идёт параллельно; ждать завершения соседней игры не нужно.

```powershell
git switch -c tetris
# Для сапёра: git switch -c minesweeper
idf.py -DIDF_TARGET=esp32 build
python tools/run.py --no-build
```

Каждый меняет файлы своей `games/<игра>`. Общие файлы и заголовки меняет Дмитрий.
SDK, сборки, личные пути и настройки окружения не коммитятся. Каждый собственный
файл программы — не больше 2000 строк. Doxygen добавляется вместе с реализацией.

## Как заменить заглушку

В `games/tetris/tetris.h` и `.cpp` уже есть класс `Tetris` с пятью методами `Game`.
Аналогично `Minesweeper` и `Pong`. Удалить приватный `Stub stub_`, включение `stub.h`
и перенаправления в `.cpp`; вместо них добавить своё состояние и механику.
Имена класса, файлов и публичные сигнатуры сохраняются.

| Метод | Обязанность игры |
| --- | --- |
| start(Settings) | Полностью сбросить партию; принять сложность, уровень, seed и первый ход |
| handle(Input) | Обработать готовое действие; клавиши P/R/Q сюда не приходят |
| update(ms) | Продвинуть игру на переданное время; пауза уже исключена |
| draw(Screen&) const | Рисовать через общий экран, не менять логику и генератор |
| result() const | Вернуть Playing/Won/Lost, счёт, уровень, время и данные первого хода |

Нет собственного бесконечного цикла, UART, разбора ANSI, задержек, меню и чтения
реальных часов. `Won` завершает текущий конечный уровень; следующий запускает
оболочка. В тетрисе обычное повышение уровня сохраняет `Playing`.

## Заголовки и координаты

- `common/game.h`: `Game`, `GameId`, `Difficulty`, `State`, `Settings`, `Result`.
- `common/input.h`: `Input`, `InputType`; приложение использует `InputReader`.
- `common/screen.h`: `Screen` с локальным полем 72×34 и панелью 21×34.
- `common/theme.h`: общая палитра; цвета не подменяются личной темой игры.

`text`, `number`, `frame`, `fill`, `cell` используют координаты символов внутри поля.
`cell(x,y,...)` занимает **два столбца**, но x задан в столбцах, а не в клетках.
`panelText` / `panelNumber` рисуют в боковой панели. Методы `canvas*`, `begin` и
`flush` предназначены оболочке; игра их не вызывает.

Мышь приходит относительно поля: x=0..71, y=0..33. Клавиатура — с x=y=−1.
`PointerMove` с x=y=−1 означает уход указателя: нужно убрать подсветку.
Внешние щелчки играм не передаются. Это уточнение сохраняет зафиксированный тип Input.

Для сапёра масштаб и отступы определяются методом `boardLayout()`.
Сначала проверить попадание в прямоугольник, затем вычислить колонку
и строку по размерам клетки.
`Confirm` и `Open` открывают клетку; `Flag` меняет флаг.
`PointerLeft` открывает, `PointerRight` меняет флаг, `PointerMove` обновляет наведение.

`Settings.seed` — единственный источник начальной случайности. Игра имеет собственный
детерминированный генератор. `draw`, подсказки и движения мыши не расходуют случайные
числа без игрового действия. Пауза не вызывает update; R повторяет тот же старт.
У сапёра R после первого открытия также повторяет этот первый ход автоматически.

## Требования к играм

### Тетрис — Паша

- Поле 10×20, семь тетромино, движение и поворот с проверкой столкновений.
- Автопадение, фиксация, очистка полных линий и опускание остальных.
- Поражение при заблокированном появлении; бесконечная партия.
- Уровень повышается каждые 10 линий; три сложности меняют начальный темп.
- Счёт, линии и уровень видны. Пробел ничего не делает; мгновенного сброса нет.
- Контур приземления, следующая фигура, серии очисток и неблокирующие эффекты.
- Серия прерывается после фигуры без очистки. Численные скорости и очки записываются
  в таблице параметров игры; они ещё не заданы общей основой.

### Сапёр — Тёма

- Генерация при первом открытии; выбранная клетка безопасна. Решаемость всех полей
  без угадывания не обещается. Победа — открыты все безопасные клетки.
- Флаги только на закрытых клетках; обычное открытие не снимает флаг.
- Пустая область раскрывается вместе с числовой границей.
- Таймер идёт с первого открытия до исхода партии, без пауз.
- Пять размеров и три сложности:

| Размер | Лёгкая | Средняя | Сложная |
| --- | ---: | ---: | ---: |
| 8×8 | 6 | 10 | 13 |
| 10×10 | 10 | 15 | 20 |
| 12×12 | 14 | 22 | 29 |
| 14×14 | 20 | 29 | 39 |
| 16×16 | 26 | 38 | 51 |

- Раскрытие соседей открытой цифры при совпадении числа флагов; ошибочная разметка
  может привести к взрыву. Реальное положение мин не подглядывается.
- Подсветка соседей выбранной/наведённой открытой цифры.
- Счётчик бандан выдерживает 256. `Result.score` — число впервые открытых
  безопасных клеток. На экране этот показатель называется «Цена ошибки».
- После обоих исходов можно посмотреть раскрытое поле. «Начать заново»
  сохраняет размер и сложность и создаёт новую партию с другим seed.
- Фактический первый ход возвращается в Result; если он задан в Settings,
  генерация и открытие автоматически воспроизводятся в start.

### Пин-понг — Дмитрий

- Игрок снизу, ковбой сверху; ←/→ или A/D и мышь. Ракетка 10 символов,
  скорость игрока 54 столбца/с, ковбоев 36 столбцов/с. Клавиша двигает цель на четыре столбца;
  мышь задаёт цель, без телепортации. Уход указателя не двигает ракетку.
- Физика с фиксированной точностью 10000, шаг 10 мс; единица по x занимает два
  символа, дробные позиции дают одноколоночную отрисовку. Поле физики 36×30,
  а не дискретная доска: пробка и ракетки используют верхние 72×30 символов общей области 72×34.
- Боковые отражения, столкновения с ракетками, угол по контакту 10..60°,
  один матч до 5 очков без преимущества в два. Подача через 700 мс в сторону
  пропустившего. Result.score — очки человека, полное табло рисует Pong.
- Перед стартом выбор уровня 1..3; скорости 12/16/20 единиц/с. Четвёртый —
  опционально после победы на третьем или по коду, два бота на отдельных половинах,
  общий счёт ботов и стартовая скорость 20. После четвёртого продолжения нет.
- Время розыгрыша идёт только в полёте: ×1.1 на 10-й секунде, затем каждые 5 с,
  максимум ×2. Очко/R сбрасывают множитель; пауза/подача не ускоряют мяч.
- Сложность меняет только ошибку точки перехвата: ±9/±6/±2 символьных колонок.
  На Hard примерно 1/8 подлётов имеет ошибку 6..10 колонок. Смена сложности не
  меняет длину/скорость ракеток или стартовую скорость мяча. Бот учитывает стены.
- Короткий след прошлых положений, число ударов, подсветка очка; без прогнозной
  линии для игрока. Все эффекты обновляются из игрового времени, draw чистый.

## Коммиты и проверки

Публикация Дмитрия разделена на два коммита: **«Новые требования и экран»**
(контракт и общий экран), затем **«Пин-понг и испытания»** (вся игра,
боты, ускорение, эффекты, P2 и копирование). Прежний план четырёх коммитов
заменён этим решением пользователя. Второй коммит проходит через PR в main.

У коллег остаются три собственных этапа в игровых ветках:
«Механика тетриса» → «Уровни тетриса» → «Улучшения тетриса»;
«Механика сапёра» → «Поля сапёра» → «Улучшения сапёра».
Каждый этап собирается и запускается перед push/PR в main. Названия на русском.
Персональные файлы-передачи не включаются в Git.

Windows: `powershell -ExecutionPolicy Bypass -File tools/test.ps1` проверяет QEMU,
GDB и нативную консоль. `tests/core.cpp` проверяет оболочку с игровыми двойниками,
включая победы и переходы, которых нет в заглушках. При наличии компилятора ПК:
`cmake -S tests -B build-host`, `cmake --build build-host`,
`ctest --test-dir build-host --output-on-failure`.
Компилятор ПК не обязателен для команды; Windows/QEMU-тесты используют только ESP-IDF.

Полная фиксация меню и формата кода — [docs/SPEC.md](docs/SPEC.md).

Уточнение Понга: максимальная ошибка лёгкого бота уменьшена с ±6
до ±4,5 единицы физики (на 25%); средняя и сложная не менялись. Победа Понга
подписана «Соперник переигран». Афиша правил имеет ширину 64 символа,
как меню; кактусы и перекати-поле рисуются на общем фоне всех экранов меню.


## Финальные изменения оболочки

Контракты `Settings`, `Result`, P2 (18 символов) и координаты игровых событий
сохранены. Игровым классам не нужно обрабатывать буфер обмена или новые действия.
`InputType` 0..21 сохраняют номера; добавлены `Paste=22`, `PasteBegin=23`,
`PasteEnd=24`, `PasteFailed=25`, `PasteText=26`, `Redraw=27`.

На странице ввода кода ↑ / Ctrl+V запрашивают буфер: `Screen::requestPaste()`
выводит OSC52 `ESC]52;c;? BEL`. Лаунчер принимает только один P2-код и отвечает
`ESC[200~кодESC[201~` либо `ESC[903~`. Текст вставки не превращается в P/Q/R/C;
запуск требует Enter. Через 2 с без ответа меню оставляет ручной ввод доступным.
`Menu::takePasteRequest()` потребляется главным циклом. `ESC[930~` инвалидирует
кадр при подключении, без сброса партии. Протокол копирования не изменён.

`python tools/run.py --port COM5` подключает тот же терминальный адаптер к
USB-UART (115200). Игровая логика и генерация P2 работают на ESP32; Windows
обслуживает клавиатуру, мышь и буфер. Без лаунчера код можно набрать вручную.

«Управление» переименовано в «Краткая сводка»: правила заказов тетриса,
раскрытия соседей цифры сапёра и бонусного уровня понга собраны в одной афише.
Бонус предлагается после победы на скоростном уровне 3 при любой сложности;
после уровня 2 бонуса нет. В интерфейсе понга: ковбои, враг, скорость пробки,
«Соперник переигран», «Проиграл дуэль», «СЧЁТ ДУЭЛИ». В сапёре — динамиты.
Кружка справа внизу — декорация меню, не часть игрового поля.
