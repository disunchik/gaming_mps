# Промпт, паяльник, три ствола

Общая основа сборника одиночных игр для ESP32: тетрис, сапёр и пин-понг.
**Пин-понг реализован:** клавиши и мышь, три обычных уровня, три сложности,
ускорение долгих розыгрышей и бонусный четвёртый уровень с двумя ботами.
Тетрис и сапёр пока в разработке; их заглушки позволяют проверить интеграцию.
Работают меню, пауза, повтор, коды P2/P1 и копирование кода в Windows.

Оболочка и вывод выполняются прошивкой ESP32. QEMU от Espressif эмулирует МК,
а Python-запускатель соединяет его UART с терминалом. Запускатель не содержит
игровых правил. Эмулятор разрешён организатором при отсутствии МК.

## Среда

- Windows 10/11, терминал с ANSI/UTF-8 размером не меньше **100×40**.
- ESP-IDF **v5.5.1**, цель `esp32`, C++17, GCC, CMake и Ninja из установки ESP-IDF.
- `qemu-xtensa`, `xtensa-esp-elf-gdb`; Python из окружения ESP-IDF.
- Git и VS Code с расширениями Espressif ESP-IDF и Microsoft C/C++.
- Doxygen для генерации документации; для сборки прошивки он не нужен.

WSL, Arduino IDE, PlatformIO, MinGW и платная лицензия эмулятора не требуются.
Версия SDK зафиксирована для воспроизводимости, а не как самая новая.

В терминале активированного ESP-IDF доустановить QEMU при необходимости:

```powershell
python "$env:IDF_PATH\tools\idf_tools.py" install qemu-xtensa
```

Затем открыть новый терминал ESP-IDF.
Инструкция Espressif: [QEMU в ESP-IDF v5.5.1](https://github.com/espressif/esp-idf/blob/v5.5.1/docs/en/api-guides/tools/qemu.rst).

## Сборка и запуск

```powershell
git clone https://github.com/disunchik/gaming_mps.git
cd gaming_mps
idf.py -DIDF_TARGET=esp32 build
python tools/run.py --no-build
```

Либо открыть папку в VS Code и использовать задачи «Собрать ESP32» и
«Запустить QEMU с мышью». `Run-QEMU.cmd` активирует ESP-IDF, собирает проект
и запускает его. `ESP-IDF.cmd` открывает только активированный терминал.

Автоактивация ищет ESP-IDF v5.5.1 в реестрах установленного EIM на C: и D:.
При другом расположении открыть готовый терминал ESP-IDF либо задать
`GAMING_IDF_ACTIVATE` — путь к своему скрипту активации. Проект и сборки могут
находиться на D:; SDK в Git не входит.

Выход: **F10**, **Ctrl+]** или Ctrl+C. Запускатель восстанавливает режим консоли
и останавливает только принадлежащий ему QEMU. `idf.py qemu monitor` доступен,
но основным способом управления мышью служит `tools/run.py`, читающий нативные
события Windows.

## Управление

| Действие | Управление |
| --- | --- |
| Выбор пункта | ↑/↓, W/S или наведение мыши |
| Подтверждение | Enter или ЛКМ |
| Изменение настройки | ←/→, A/D или щелчок по строке |
| Пауза / продолжение | P |
| Повтор тех же начальных условий | R |
| Копировать доступный код | C, кнопка под полем или пункт паузы |
| В меню / назад | Q или Esc |
| Ввод кода | Символы, Backspace; Enter — проверить, Esc — отменить |

Справа у Понга — счёт, уровень, сложность и удары розыгрыша; технических
координат и seed в интерфейсе нет. Обычные уровни 1–3 выбираются перед матчем,
четвёртый предлагается после победы на третьем. Скорость растёт после 10 секунд
розыгрыша, далее каждые 5 секунд на 10%, до ×2; очко сбрасывает ускорение.

Новая игра получает новый seed, R повторяет прежний старт. Новый код
`P2-XXXX-XXXX-XXXXX` — 13 символов данных, полный seed и CRC16. Старые P1
принимаются. У реального сапёра код появится после первого открытия.
Кнопка «Копировать [C]» работает через Windows-запускатель, подтверждение приходит
после записи в системный буфер; остальные терминалы получают понятный отказ.

**Для разработчиков:** размеры поля, преобразование мыши и полная миграция
формата кодов описаны в [DEVELOPMENT.md](DEVELOPMENT.md). Публичный Game сохранён.

## Проверки и отладка

После сборки, из терминала ESP-IDF:

```powershell
python tools/smoke.py
python tests/native_console.py
```

Первая проверка запускает прошивку в QEMU и проверяет меню, оставшиеся заглушки, настоящий Понг, клавиши,
мышь, границы, паузу, повтор, новые и повреждённые коды. Затем GDB останавливается
в `app_main` и выполняет два шага по исходнику. Дополнительно `python tests/test_clipboard.py` проверяет фрагментацию OSC52.
Вторая открывает отдельную консоль
Windows и проверяет цепочку нативных событий → запускатель → UART → прошивка → экран 100×40, а также
копирование с чтением реального буфера Windows. Содержимое буфера восстанавливается.
Она подаёт синтетические записи в очередь своей консоли; физические движения и
клики пользователя этим тестом не подтверждаются. Логи и восстановленные из UART
кадры создаются в `artifacts/`, вне Git.

Ручная отладка:

```powershell
# Терминал 1: приложение остановлено до подключения отладчика
python tools/run.py --no-build --debug
# Терминал 2, в этой же папке и среде ESP-IDF
idf.py gdb
```

В GDB: `thbreak app_main`, `continue`, `next`, `next`.
Это GDB-сервер QEMU; физический JTAG не проверялся. На плате параметры JTAG
зависят от отладочного адаптера.

## Документация

```powershell
powershell -ExecutionPolicy Bypass -File tools/docs.ps1
```

Если Doxygen уже добавлен в PATH, достаточно `doxygen Doxyfile`. При другом расположении
передать скрипту `-Doxygen <путь-к-doxygen.exe>`. Результат — `docs/html/index.html`. Doxygen проверяет описания функций, классов,
глобальных объектов и макросов прошивки. [Doxygen для Windows](https://www.doxygen.nl/download.html).
Правила команды — [DEVELOPMENT.md](DEVELOPMENT.md), исходное задание —
[docs/TASK.md](docs/TASK.md), спецификация — [docs/SPEC.md](docs/SPEC.md).
